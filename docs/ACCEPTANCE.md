# 平台验收说明（Acceptance Guide）

> 本文档把散落在 `spec.md`（§5 阶段出口 / §8 里程碑）、`docs/issues/*.md`（23 张工单验收标准）、
> `pilot-launch-checklist.md`（试点真人动作）里的验收要求，整合成一份可执行的验收操作手册。
> 用于回答「某张工单 / 某个里程碑 / 某个阶段，到底怎么算通过」。

---

## 1. 验收总览：三层 + 四里程碑 + 四出口

平台验收分三层，由细到粗：

| 层 | 对象 | 谁来验收 | 产出 | 判定 |
|---|---|---|---|---|
| **工单验收** | 23 张工单各自的「验收标准」checkbox | 工程师 + 对应业务/安全人 | 实测证据（命令输出/事件链/测试结果） | 逐条勾选通过 |
| **里程碑验收** | M0 / M1 / M2 / M3（`spec §8`） | 业务方 + 管理员 + 安全/财务 + 种子用户 | 里程碑出口判定 | 出口条件全满足 |
| **阶段出口** | Phase 0 / 1 / 2 / 3（`spec §5`） | 平台负责人（评审会） | 进入下一阶段的门票 | 出口条件全满足 |

**验收角色分工**：

| 角色 | 验什么 | 对应工单 |
|---|---|---|
| 工程师 | 功能/性能/可靠性实测，留证据 | 01/02/03/04/06/08/09/19/20/21 |
| 种子用户 | 真实任务端到端复验 + 反馈 | 05 |
| 管理员 | 后台操作闭环（找会话/禁用/上下架/配额） | 10/12/13/14/16 |
| 安全/IT | 越权拦截、脱敏、离职回收、数据分级 | 07/13/14/15/18 |
| 财务 | 成本报表口径 | 15 |
| 业务方 | 场景清单确认、模板实际使用 | 05/17/21/22/23 |

## 2. 里程碑验收（M0–M3）

### M0 — 单链路打通（第 2 周末）

**覆盖工单**：01 开发环境 · 02 公司 profile · 03 模型网关 · 04 首个 MCP · 05 试点运行
**出口标准**：≥1 个真实任务由 Agent 端到端完成；确定平台主用场景清单。

**验收操作步骤**：

1. 新机器按 `RUN-LOCALLY.md` 30 分钟内跑起 `dsh web`（工单 01）。
2. 新会话加载公司 persona，危险工具不可见（工单 02）。
3. 选 1 名种子用户，让其用**自己的原话**提一个真实任务（样例：跨市出差交通费上限）。
4. 观察 Agent 是否自动调用 `mcp__kb__knowledge_search` 等 MCP 工具，返回**带出处**的答案（工单 04）。
5. 核对答案是否正确；在 `pilot-kit.md §2` 任务样例集记录：目标 / 工具链路 / 耗时 / 是否端到端完成。
6. 满足「≥1 真实任务端到端」→ M0 通过；同时产出主用场景 Top 5–10 清单交业务方确认（工单 05）。

**判定**：任一真实任务端到端完成 + 场景清单经业务方签字 = M0 通过。

---

### M1 — 50 人可用（第 6 周末）

**覆盖工单**：06 控制面 · 07 SSO · 08 共享会话 · 09 集中凭据 · 10 管理后台 · 11 试点扩量
**出口标准**：50 名员工钉钉扫码登录；会话跨设备可恢复；管理员可看到每会话审计记录。

**验收操作步骤**：

1. 开通 50 个账号；员工用钉钉扫码登录进入个人工作区（工单 07）。
2. 员工在设备 A 开一段会话，换设备 B 登录 → 会话**无缝续聊**（工单 08）。
3. 管理员在后台 3 步内检索到该会话，看到完整审计事件链（工单 10）。
4. 禁用 1 个用户 → 其实例立即回收、新请求被拒、离职用户立即失权（工单 07/10）。
5. 验证密钥明文不出现在任何 admin/审计 payload，轮换后下一任务即用新密钥（工单 09）。
6. 50 并发模拟下实例按预算拉取/回收，无资源泄漏（工单 06）。

**判定**：SSO 登录 + 会话恢复 + 审计可见三项全部通过 = M1 通过。

---

### M2 — 治理完备（第 10 周末）

**覆盖工单**：12 Agent 商店 · 13 RBAC · 14 审批流 · 15 审计看板 · 16 配额限流 · 17 RAG
**出口标准**：管理后台可完成 Agent 上架/下架；财务口径成本报表生成；越权工具调用被拦截并留痕。

**验收操作步骤**：

1. 管理员上架一个 Agent → 普通员工立即可见可选用；下架后新会话不可选（工单 12）。
2. 普通员工尝试执行危险工具/管理操作 → 被拦截并留痕；开发者可独立调试（工单 13）。
3. 敏感工具调用无有效授权 → fail-closed 拦截；授权可查/可撤销（工单 14）。
4. 财务口径成本报表生成、可导出；审计数据无密钥明文（工单 15）。
5. 单用户打满配额不影响他人；超限提示明确；配额调整 1 分钟内生效（工单 16）。
6. 自然语言提问命中知识库并带 citation；越权检索返回空/拒绝（工单 17）。

**判定**：商店上下架 + 成本报表 + 越权拦截留痕三项全部通过 = M2 通过。

---

### M3 — 自动化规模（第 14 周末）

**覆盖工单**：18 IM 机器人 · 19 任务队列 · 20 定时 Agent · 21 工作流模板 · 22 反馈闭环 · 23 全量推广
**出口标准**：IM 入口 + ≥3 场景自动化 + 定时任务上线；机器人周活 > 60% 试点部门员工；事故可复盘。

**验收操作步骤**：

1. 员工在钉钉 @机器人 → 得到真实回答，多轮上下文连贯；长任务结束主动推送结果（工单 18）。
2. 同用户任务串行、跨用户隔离；任务崩溃自动重试、可人工取消、执行链可回溯（工单 19）。
3. 定时任务按 cron 准时触发，失败重试+告警符合预期，至少 1 个高频场景（如周报）跑通（工单 20）。
4. ≥1 个模板被业务方实际投入使用，产出与人工基线相当（工单 21）。
5. 反馈率 ≥10% 活跃会话；关键场景基准集回归通过率持续上升（工单 22）。
6. SLA 连续 4 周达标、事故均可复盘、运维手册交付（工单 23）。

**判定**：IM 入口 + ≥3 场景自动化 + 定时任务三项通过 = M3 通过。

## 4. 验收执行流程（怎么走一遍）

### 4.1 顺序（依赖驱动）

按 `enterprise-shell §8` 的依赖顺序走，不要跳步：身份/SSO → 会话路由+编排 → 审计 → 目录 → 配额/审批 → 任务队列 → 后台整合。
对应里程碑：M0（01–05）→ M1（06–11）→ M2（12–17）→ M3（18–23）。

### 4.2 记录方式

每完成一项验收，做三件事：

1. **勾选** `docs/issues/XX-*.md` 里的验收标准 checkbox，并把工单 `Status` 从 `open` 改为 `closed`。
2. **留证据**：把实测命令输出 / 事件链 / 测试结果贴进该工单的 `Comments`（现有工单已有此格式，照做）。
3. **回写快照**：更新 `docs/STATUS.md`（工单状态 + 实测证据列）与 `docs/map.md`（勾掉对应 Fog 项）。

### 4.3 验收评审会（每个里程碑一次）

每个里程碑结束开一次验收会，参加人按「验收角色」表。会上**逐条过验收标准**，判定三种结果：

- **通过** → 关闭该里程碑涉及的工单，解锁下一阶段。
- **有条件通过** → 记录遗留项进 backlog（如「步骤级轨迹」已决定不补），继续前进。
- **不通过** → 回到该工单，明确阻塞项（按 MISSION 三分类：目标不清 / 缺工具 / 缺权限）。
